Attributes vs. Methods:
        1. Attributes represent the state of the object (the "nouns").

        2. Methods represent the actions of the object (the "verbs").

        3. Since "Instance Variable," "Object Variable," and "Class Variable" all refer to ways to store data, "Method" stands out as the functional component.

==> The Four Pillars of OOP:::::::

A. Encapsulation
    Encapsulation restricts direct access to data to prevent accidental modification. In Python, we use underscores to indicate "private" variables.
        1. _variable : Protected (Internal use).
        2. __variable : Private (Name mangling applied).

    why use it????
         To protect data integrity and prevent external code from accidentally corrupting an object's internal state.
    when to use????
        Whenever you want to validate data before it is saved or hide compexity of data stored.
    where to use????
        any system requiring data securitysuch as banking systems (account balance), user profiles (passwords)


B. Abstraction (The "User Interface")
    Hiding complex implementation details and showing only the essential features of an object. 
    It focuses on what an object does rather than how it does it.

    Why use it??? 
        To reduce complexity and allow users to interact with a system without needing to understand its internal mechanics.
    When to use it???
        When you are building a framework or a library where the end-user only needs to know the interface (buttons/methods) and not the logic.
    Where to use it??? 
        Remote controls, car dashboards, or API endpoints.


C. Inheritance
    Inheritance allows one class (Child) to derive attributes and methods from another class (Parent).
        1. Single Inheritance: Child inherits from one parent.
        2. Multiple Inheritance: Python supports inheriting from multiple classes.
        3. super() : Used to call methods from the parent class.

    we inherit:::
        -->non-private attributes
        -->non-private methods
        -->constructor(or other magic method)

    Why use it??? 
        To promote code reusability. You write common code once in the parent class and specialized code in the child classes.
    When to use it??? 
        When there is an "is-a" relationship (e.g., a Car is a Vehicle, a Dog is an Animal).
    Where to use it??? 
        Game development (different types of enemies), UI frameworks (different types of buttons).


    --->we cannot access  private attribute or method of our parent class

D. Polymorphism (The "Many Faces")
    The ability of different objects to respond to the same method call in their own specific way. (Greek: poly = many, morph = forms).

    Why use it??? 
        To allow for flexibility and extensibility. You can process different types of objects using the same interface.
    When to use it??? 
        When you have a list of different objects that all share a common action but perform it differently.
    Where to use it??? 
        Payment systems (paying via Credit Card vs. PayPal), Graphics (drawing a Circle vs. a Square).

==>How isinstance(obj,class) Works with Inheritance????
        One of the most powerful features of isinstance() is that it supports Inheritance. If you create a more specific class (like Dog) that inherits from Animal, a Dog object is considered an instance of both Dog and Animal.

isinstance() vs type()

Feature	                  isinstance(obj, Class)	                   type(obj) == Class

Inheritance	            Supports it (checks subclasses).	       Does not support it (checks exact type).
Flexibility	            Can check against a tuple of types.	        Only checks one type at a time.
Best Practice	        Recommended for most logic.	                Used only when an exact match is required.
